# Public failure matrix

The test references below are exact repository symbols. “Gap” is intentionally honest:
an adjacent unit test is not evidence of an end-to-end crash simulation.

| Scenario | Expected durable job/slot state | Current test evidence | Gap |
| --- | --- | --- | --- |
| Coordinator killed during launch | The dispatch claim remains durable, is reconciled to `dispatch_failed`, and cannot launch again until explicit retry. | `tests/entities/plan/test_plan_store.py::test_dispatch_reconciles_coordinator_killed_after_claim_before_launch`; `tests/app/runtime/test_orchestrator_runner.py::test_plan_dispatch_materializes_private_brief_and_starts_exactly_once`; `tests/features/agent_runner/test_job_reconciliation.py::test_reconcile_kills_verified_child_after_coordinator_death` | The test kills the exact coordinator process at the `PlanDispatcher` launch callback before any external runner starts. It does not simulate a crash after a runner has been spawned; that boundary is covered by the coordinator-child reconciliation drill. |
| Worker killed/interrupted during finalization | Job is terminal/partial or finalizing; checkpoint and inbox must be durable before cleanup; dirty slot remains quarantined until replay safely releases it. Once `slot_released` is durable, replay validates the immutable checkpoint ref without constraining or quarantining the slot's newer checkout. Reconcile can also recover the legacy poisoned state where an older replay overwrote `slot_released` after the clean slot had already moved to another branch. | `tests/features/agent_runner/test_job_reconciliation.py::test_reconcile_replays_exact_process_killed_after_checkpoint_before_cleanup`; `tests/features/agent_runner/test_job_reconciliation.py::test_reconcile_replays_crash_after_terminal_transition`; `tests/features/agent_runner/test_job_reconciliation.py::test_reconcile_reuses_checkpoint_after_crash_before_slot_release`; `tests/features/agent_runner/test_job_reconciliation.py::test_reconcile_after_checkpoint_release_does_not_reinspect_reused_slot`; `tests/features/agent_runner/test_job_reconciliation.py::test_released_checkpoint_damage_does_not_quarantine_reused_slot`; `tests/features/agent_runner/test_job_reconciliation.py::test_reconcile_recovers_legacy_checkpoint_failure_after_slot_reuse`; `tests/features/result_handoff/test_result_handoff_orchestrator.py::test_checkpoint_cleanup_failure_keeps_slot_dirty_and_review_ref_visible` | The drills cover exact-process termination before cleanup, a crash after slot release followed by a different checkout, and recovery of the persisted legacy failure shape. They do not interrupt an in-flight Git subprocess, so filesystem-level Git-command races remain outside this bounded simulation. |
| PID reuse or durable identity mismatch | Reconciliation must not terminate the unrelated process; job and slot remain quarantined. | `tests/features/agent_runner/test_job_reconciliation.py::test_reconcile_does_not_terminate_live_process_with_mismatched_durable_identity`; `tests/features/agent_runner/test_process_identity.py::test_verified_termination_refuses_reused_pid_identity` | The drill uses a live process with deliberately mismatched durable identity. Exact OS PID reuse is not reliably forceable and is not claimed. |
| SQLite contention | Transaction is serialized or fails visibly; no duplicate dispatch/partial durable claim. | `tests/entities/plan/test_plan_store.py::test_cross_process_sqlite_lock_serializes_one_durable_dispatch_claim`; `tests/entities/plan/test_plan_store.py::test_ready_task_claim_is_atomic_across_two_plan_store_instances` | The lock holder and claimant are separate subprocesses synchronized with ready/release files; the test covers one bounded contention window, not arbitrary filesystem or database failure. |
| Workspace edited after checkpoint | Cleanup fails closed; checkpoint/ref and inbox remain visible; slot remains dirty. | `tests/features/result_handoff/test_slot_checkpoint.py::test_cleanup_fails_closed_when_another_process_edits_after_checkpoint`; `tests/features/result_handoff/test_result_handoff_orchestrator.py::test_checkpoint_cleanup_failure_keeps_slot_dirty_and_review_ref_visible` | The editor completes before cleanup is invoked; this proves the durable checkpoint is preserved on cross-process interference but not a simultaneous Git-command race. |
| Repeat dispatch/recovery after restart | Existing claim is not duplicated; failed dispatch is blocked until explicit retry; restart resumes from SQLite. | `tests/entities/plan/test_plan_store.py::test_cross_process_sqlite_lock_serializes_one_durable_dispatch_claim`; `tests/entities/plan/test_plan_store.py::test_dispatch_failure_is_durable_and_not_automatically_reclaimed`; `tests/app/runtime/test_plan_cli.py::test_cli_restart_requires_explicit_retry_after_failed_dispatch` | The CLI drill forces a launch failure before an external worker starts; it proves dispatch ownership and retry persistence, not recovery of a partially started external worker. |
| Worker exits 0, dirty workspace, `result.md` never written | Job still ends failed (`stopped_dirty_after_failure`); checkpoint is created and, on a native/controller route, controller gates run against it before cleanup, so the durable review-inbox record carries gate verdicts instead of only a diff; `review_ready` stays false because the placeholder result is `Status: blocked`, and missing worker `verification.json` still independently blocks root acceptance. | `tests/features/result_handoff/test_result_handoff_orchestrator.py::test_missing_result_salvage_runs_controller_gates_against_checkpoint`; `tests/features/result_handoff/test_result_handoff_orchestrator.py::test_dirty_after_other_failure_still_skips_controller_gates` | The drill sets `runner_failure` and dirties the slot directly rather than driving a real agent process to that exact exit shape; the scope is intentionally narrow to `runner_failure == "exited_without_result"` + `stopped_dirty_after_failure` — every other dirty-after-failure cause (timeout, guardrail violation, tool-call budget, ...) is proven to keep the prior no-gates behaviour by the second test, not extended. |
| Detached dispatcher exits while a worker starts | POSIX workers start in a new session; Windows workers use a new process group, so the lease and heartbeat do not depend on the short-lived caller. | `tests/features/lifecycle_cleanup/test_slot_lifecycle.py::test_background_worker_is_detached_from_short_lived_dispatch_caller` | This locks the OS spawn contract; configured live AGY smoke remains the end-to-end proof. |
| Cleanup retries after a crash or sees a moved/reused resource | The operation ID binds generation, filesystem and repository identity, HEAD/checkpoint, remote URL, and canonical tip. Retry completes the same operation, is a no-op, or quarantines it. | `tests/features/lifecycle_cleanup/test_slot_lifecycle.py` | Audit and bounded polling only enqueue; they never apply cleanup. |

Operational response: preserve the database, run `status`/`plan summary`, reconcile
without termination first, inspect the slot and inbox, then retry only after the durable
state explicitly permits it. Root acceptance remains a separate decision.
